# Отчёт по лабораторной работе: GitHub Actions

1. **Из каких элементов состоит workflow и как они вложены?**
Workflow (YAML-файл в .github/workflows/) содержит событие (on), внутри jobs находятся jobs, у каждого job есть runner (runs-on) и steps. Step это команда (run) или готовый action (uses).

2. **Чем job отличается от step?**
Job это набор шагов, выполняемых на одной виртуальной машине, jobs по умолчанию идут параллельно. Step это отдельная команда или action внутри job, шаги идут последовательно.

3. **Чем запуск по push отличается от запуска кнопкой (workflow_dispatch)?**
Push запускает workflow автоматически при отправке коммита в репозиторий. workflow_dispatch запускается вручную кнопкой Run workflow во вкладке Actions.

4. **Как безопасно передать в workflow пароль или токен?**
Через секреты репозитория (Settings → Secrets and variables → Actions) и обращение `${{ secrets.NAME }}`. В логе значение скрывается звёздочками, в коде его хранить нельзя.

5. **Что такое артефакт и зачем он нужен?**
Артефакт это файл, сохранённый после выполнения job. Нужен, чтобы передать файл из одного job в другой (каждый job работает на отдельной чистой машине) и чтобы скачать результат сборки.

6. **Как заставить один job дождаться другого? Зачем нужен линтер, если есть тесты?**
С помощью ключа `needs: имя_job`. Без него jobs идут параллельно, и show падает, потому что build не успел создать артефакт. Линтер находит ошибки и плохой стиль без запуска кода, а тест проверяет только то, что в него заложено. В PR тест был зелёным, а lint красным (shellcheck нашёл код без кавычек).
